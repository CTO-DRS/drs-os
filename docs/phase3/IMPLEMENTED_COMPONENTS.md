# Phase 3 — Implemented Components

Status: implementation record (Phase 3, 2026-10-16). Every row states

## 1. Pure-Kotlin core modules (compiled & tested in this sandbox)

### components/foundation — `com.drs.os.foundation`
- `KvStore` — deterministic line codec (percent-encoding, sorted keys,
  strict decode: malformed line / duplicate key / bad escape = error).
  Persistence foundation for settings and rules.
- `MiniJson` — strict RFC 8259 parser (no comments, no trailing commas,
  duplicate keys rejected, unpaired surrogates rejected, depth ≤ 64,
  bounded input protection) + canonical writer. Serves rule
  serialization and the differential vectors.
- Status: **COMPILED, 25/25 unit tests PASS** (JVM, kotlinc 2.0.21).

### components/engine-core — `com.drs.os.engine`
- `Model` — Rule / Trigger / Condition / EventContext / Decision /
  ActionRequest / AuditRecord, wire-compatible with the Phase 2 Python
  reference.
- `Validation` — closed action registry (6 actions, none
  security-sensitive in v1) and rule validation identical in acceptance
  to the reference; the consent gate for future security-sensitive
  actions is enforced and tested.
- `Evaluator` — pure evaluation with the exact spec §3 decision order;
  midnight-spanning time windows; deterministic multi-rule selection.
- `RuleJson` — strict wire codec (rejects unknown fields, wrong types,
  duplicate keys).
- `host` — host-layer helpers per spec §4: calendar-minute dedup,
  per-day run counters, append-only audit (11 fixed keys, no personal
  data), execution coordinator (per-trigger action limit, cancellation,
  stable error classifications), persistence snapshot/restore with
  strict recovery.
- Status: **COMPILED, 104/104 tests PASS**, including **34/34
  differential tests** against `tools/automation-reference/test_vectors.json`
  generated by the Python reference — the two implementations agree on
  every case.

### components/security-core — `com.drs.os.security`
- Four-state model (PASS / WARNING / UNAVAILABLE / NOT_CHECKED) with
  evidence; missing/failed provider inputs become honest UNAVAILABLE,
  never guesses; a crashing check is contained as internal-error.
- `DrsChecklistV1` — six deterministic checks (screen lock, device
  encryption, patch level, verified boot, permission inventory,
  automation review) with pinned input contracts.
- `ChecklistPresenter` — severity ordering, summary counts, overall
  state, stable resource keys for the ar/en resources.
- Status: **COMPILED, 18/18 tests PASS**.

### components/settings-core — `com.drs.os.settings`
- Schema-validated settings (Arabic default language, theme, automation
  policy), KvStore persistence, structural-corruption → whole-document
  defaults (no partial salvage), per-field enum recovery with recorded
  notes, unknown-version handling.
- Status: **COMPILED, 41/41 tests PASS**.

## 2. Android application modules (SOURCE IMPLEMENTED — BUILD NOT VERIFIED)

All three apps: Jetpack Compose, minSdk 29 / compileSdk 35 (standalone
choice — the platform level is confirmed at checkout), version catalogs
pinned (AGP 8.7.3, Kotlin 2.0.21, Compose BOM 2024.12.01), Arabic
DEFAULT resources with English alternative, `supportsRtl` + per-app
`localeConfig`, DRS brand tokens from branding/colors.md, zero
permissions except where stated.

### packages/apps/DRSSecurityCenter — `com.drs.os.securitycenter`
- Dashboard (banner + honest summary counts), Checklist screen (six
  checks with evidence lines and localized state words), Privacy screen
  (real self-permission introspection — zero requested — and
  resolvability-gated system-settings shortcuts), Status screen (values
  read from KeyguardManager / DevicePolicyManager /
  Build.VERSION.SECURITY_PATCH; privileged inputs labeled Unavailable
  with reasons).
- Permissions: **none** (least privilege; see AndroidManifest comment).
- Unit tests present for the presentation mapping (run on a real build;
  NOT RUN here).

### packages/apps/DRSAutomation — `com.drs.os.automation`
- Host layer for the engine: rule editor (only creatable triggers are
  ones the app actually supports — battery/charging live from the
  permissionless battery broadcast; TIME_DAILY shown as planned, not
  creatable), dry-run, run-now, enable/disable/delete, audit view.
- Persistence: rules via RuleStoreCodec + engine state snapshot in
  SharedPreferences; corrupted stores start empty and flagged.
- Executors: theme (works via public UiModeManager), DND (requires
  notification-policy access; stable failure `dnd-policy-access-denied`
  otherwise), battery saver (no public API → stable failure
  `platform-api-unavailable`, honestly documented).
- Permissions: **none**; DND special access is requested in-system,
  never silently.
- **Pure sources JVM-verified**: RuleStoreCodec +
  AutomationPresentation compiled and 9/9 tests PASS in this sandbox.

### packages/apps/DRSSettings — `com.drs.os.drssettings`
- Language selection (per-app locales via AppCompatDelegate — the
  documented mechanism), theme selection restricted to verified tokens,
  privacy/security entry points with real installed-check for DRS
  Security Center, automation policy toggles with explicit v1 scope
  note, About screen with actual BuildConfig values + honest provenance
  note + no-AI policy statement.
- Persistence through settings-core; corruption recovery surfaced in UI.
